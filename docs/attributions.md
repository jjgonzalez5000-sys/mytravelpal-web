# Data and Software Attributions

MyTravelPal builds on open data feeds and open-source libraries. Each
entry below lists the source, the license we use it under, and the
attribution obligation that comes with it. When shipping to end users,
these attributions must appear in-app (Settings → Licenses & Data) and
alongside any visual rendering derived from the data (e.g. OpenStreetMap
copyright on the map).

The canonical machine-readable copy of this list lives at
`GET /v1/attributions` on the backend so the mobile app can render it
without a rebuild each time we add a source.

---

## Map tiles and geodata

### OpenStreetMap contributors
- **What we use:** map tiles (via `tile.openstreetmap.org`), and every
  geographic query (POI search, geocoding, reverse geocoding, corridor
  discovery) that resolves against OSM data.
- **License:** Open Database License (ODbL) 1.0.
- **Attribution required:** yes, on every screen that shows OSM-derived
  content: `© OpenStreetMap contributors`.
- **Link:** https://www.openstreetmap.org/copyright

### Nominatim (openstreetmap.org)
- **What we use:** geocoding (`/search`) and reverse geocoding
  (`/reverse`) of user-typed places, plus POI discovery for hotels,
  restaurants and fuel stations along a route.
- **License:** downstream of OSM ODbL; usage policy at
  https://operations.osmfoundation.org/policies/nominatim/
- **Attribution required:** yes, `© OpenStreetMap contributors` and
  respect the 1 req/s usage policy.

### OSRM demo server
- **What we use:** route computation (`router.project-osrm.org`) as the
  fallback when a self-hosted OSRM isn't configured.
- **License:** OSRM software is BSD-2-Clause; the demo server is
  provided for demonstration only.
- **Attribution:** OSRM project + OSM data.

## Fuel prices

### Ministerio para la Transición Ecológica y el Reto Demográfico (Spain)
- **What we use:** Real fuel prices for every Spanish service station,
  refreshed daily. Endpoint: `sedeaplicaciones.minetur.gob.es`.
- **License:** Public data made available under Spain's public sector
  reuse framework (Ley 37/2007 & RD 1495/2011). No attribution *required*
  but noting the source is best practice.
- **Attribution:** "Precios: Ministerio para la Transición Ecológica y
  el Reto Demográfico (España)".

### Roulez-Éco (France)
- **What we use:** Real-time fuel prices for every French station.
  Endpoint: `donnees.roulez-eco.fr/opendata/instantane`.
- **License:** Licence Ouverte / Open Licence (Etalab) v2.0.
- **Attribution required:** yes. Standard mention: "Source :
  data.gouv.fr / Ministère de l'Économie – prix-carburants.gouv.fr".
- **Link:** https://www.etalab.gouv.fr/licence-ouverte-open-licence/

### MITE / MIMIT — Ministero delle Imprese e del Made in Italy
- **What we use:** Fuel prices for every Italian station reported to
  the Osservaprezzi Carburanti system, updated daily.
- **License:** Italian Open Data Licence (IODL 2.0) or CC-BY 4.0
  depending on the specific file. Both compatible with attribution.
- **Attribution required:** yes. "Prezzi carburanti: Ministero delle
  Imprese e del Made in Italy — Osservaprezzi Carburanti".

### Tankerkönig (Germany) — *pending integration*
- **License:** Creative Commons Attribution 4.0 International (CC-BY 4.0).
- **Attribution required:** yes. Standard mention: "Tankerkönig-Spritpreis-API
  (CC-BY 4.0)".
- **Link:** https://creativecommons.tankerkoenig.de/

## Adverse events / hazards

### NASA FIRMS (Fire Information for Resource Management System)
- **What we use:** active wildfire hotspots along the route.
- **License:** NASA data policy — free public use, attribution
  requested.
- **Attribution:** "Fire data: NASA FIRMS
  (https://firms.modaps.eosdis.nasa.gov/)".

### National weather services (via Open-Meteo)
- **What we use:** hour-level forecasts for departure-window scoring.
- **License:** Open-Meteo is CC-BY 4.0; underlying data comes from
  DWD (Germany), Météo-France, AEMET (Spain), Met Office (UK).
- **Attribution:** "Weather: Open-Meteo.com".

## Client-side software libraries

The Flutter app depends on many third-party packages, each under its
own OSS license (BSD, MIT, Apache-2.0). The complete, up-to-date list
is auto-generated by Flutter's `showLicensePage()` and accessible from
the app under **Settings → Licenses & data**. Notable packages:

| Package | License | What we use it for |
|---|---|---|
| `flutter_map` | BSD-3-Clause | Rendering the interactive map view |
| `latlong2` | BSD-3-Clause | Coordinate math and haversine |
| `flutter_riverpod` | MIT | Reactive state management |
| `http` | BSD-3-Clause | REST calls to the backend |
| `url_launcher` | BSD-3-Clause | External deep links (Google Maps, Booking) |
| `google_fonts` | Apache-2.0 | Typography from fonts.google.com |
| `share_plus` | BSD-3-Clause | Trip sharing to messaging apps |
| `intl` | BSD-3-Clause | Locale-aware date/number formatting |
| `google_sign_in`, `flutter_facebook_auth`, `sign_in_with_apple` | vendor SDKs | OAuth login |
| `flutter_local_notifications` | BSD-3-Clause | Pre-departure reminder scheduling |

Backend uses FastAPI (MIT), httpx (BSD-3-Clause), pydantic (MIT) — all
permissive, no additional obligations beyond preserving their license
files (already present in `.venv/`).

## How to add a new source

When integrating a new data feed or third-party API:

1. Add the entry above with `What we use`, `License`, `Attribution
   required`.
2. Add the same entry to the `_ATTRIBUTIONS` list in
   `backend/app/api/v1/attributions.py` so the mobile screen picks it
   up automatically.
3. If the license requires visible in-frame attribution (ODbL, CC-BY),
   add the mention to the map / list view that renders the data.
